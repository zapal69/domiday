# Domiday: правила работы

Общайся с владельцем по-русски. Сначала прочитай `START-HERE.md`,
`HANDOFF.md` и `README.md`. Это существующее работающее Flutter-приложение,
а не задание создать новое. Интерфейс на двух языках: все тексты — в
`lib/l10n/app_en.arb` и `app_ru.arb`, в коде строк для пользователя нет;
новую строку добавлять в оба файла и запускать `flutter gen-l10n`.

## Владелец и процесс

- Владелец делает полезный личный дневник путешествий с помощью ИИ и хочет
  понимать архитектуру и изменения.
- Сначала обсуждение и план; реализация только после явной команды владельца
  («делай», «начинай»). Это касается любых изменений: кода, сайта, документов,
  материалов для Play. По умолчанию каждый ответ — обсуждение, оценка,
  впечатления и предложение, без правок файлов и сервера.
- При первом запуске после переноса ничего не редактируй, не устанавливай
  инструменты и не обновляй зависимости без согласования.
- Небольшие итерации. Не переписывай приложение целиком и не добавляй
  несогласованные возможности.
- Код хранится в приватном репозитории GitHub
  `zapal69/domiday-android` (remote `origin`). Правило владельца: каждая
  версия сохраняется в GitHub — после коммита версии сразу `git push` и
  тег `vX.Y.Z` на коммит сборки (`git push --tags`). Этот репозиторий
  остаётся приватным (рабочая история). Открытая копия — `zapal69/domiday`
  (GPL-3.0, решение владельца 11.10.2026): снимок версии без истории и без
  внутренних материалов Play делает `tool/sync_public.sh`, README и LICENSE
  открытой копии лежат в `public/`; отправлять туда только после сборки
  и проверки версии. Данные, ключи и `key.properties` не публиковать и не
  коммитить; подписанный APK публикуется только в Releases открытой копии
  и на сайте. Не трогай domiday.com без команды.
- Не добавляй точные координаты, INTERNET, foreground-сервисы и любые
  новые разрешения без отдельного согласования владельца. Единственный
  выход данных наружу — «Поделиться итогами года»: картинка из кэша через
  FileProvider в системное меню, по нажатию владельца. Фоновая
  проверка остаётся выключенной по умолчанию и никогда не пишет в дневник.

## Неприкосновенные свойства

- История остаётся локально на телефоне: без аккаунта, сервера, аналитики
  и сетевых запросов. Геолокация — только приблизительная: по кнопке, при
  открытии приложения и, если владелец явно включил «Проверять в фоне»,
  фоновыми задачами WorkManager (раз в 2 часа и при появлении связи, без
  потока координат и без foreground-сервиса). Координаты не сохраняются
  и никуда не передаются, страна определяется офлайн по границам в
  приложении; фон выключен по умолчанию. Границы — Natural Earth 1:50m
  (`assets/borders.json`), спорные территории — отдельный слой
  (`assets/disputed.json`): на карте не приписаны никому и обведены
  пунктиром, при определении предлагаются обе стороны. Линии вручную не
  править и позицию по спорным территориям не занимать; это решение
  владельца («как в Google»). Список email на сайте относится
  к другому проекту.
- Не удалять историю, не делать сброс при ошибке чтения. Единственное
  удаление всего — кнопка «Очистить всё» в настройках: диалог с числом
  записей, предложение сначала сохранить копию, явное подтверждение.
- Сохранение атомарное; интерфейс сообщает успех только после записи.
- Сохранять миграции schemaVersion 1 → 2 → 3 → 4 → 5 и все значения старых
  записей. Схема 5 = 4 плюс список `plans` (планы поездок): планы не
  факты, в дни, итоги, календарные наборы и карту не попадают, пока
  владелец не подтвердит план как запись; прежние версии файл схемы 5
  отклоняют без перезаписи. Коды стран только добавляются по точному совпадению; текст
  страны в файле никогда не переписывается и не переводится; старые записи
  не становятся транзитом автоматически. Будущие несовместимые
  форматы должны отклоняться без перезаписи.
- Неизвестные дни не означают дни дома. Заполнение пробелов только после
  просмотра конкретных дат и явного подтверждения.
- Текущая страна задаётся или подтверждается пользователем, не выводится
  из последней поездки и не меняется по определению без подтверждения.
  Кандидат из определения не влияет на страну, календарь и итоги.
- Обе границы поездки включены; пересечения объединяются внутри страны и
  в общем итоге. Один день может принадлежать двум странам: общий день на
  стыке — день переезда. Пересечение от двух дней (в том числе той же
  страны) — предупреждение перед сохранением с точным списком последствий;
  «Заменить» обрезает, делит или удаляет старые записи только после этого
  подтверждения. Транзит поверх пребывания — не пересечение.
- Годовая статистика ограничена выбранным годом и сегодняшней датой.
  Домашняя страна не определяет юридическое или налоговое резидентство.

## Сборка и тесты

При смене версии поднимать три места вместе: `version` в pubspec.yaml,
`appVersionShort` и `appVersionCode` в `lib/main.dart` (из них собирается
строка версии в «О приложении» и подпись внизу экранов).

Последняя собранная версия: 1.0.1+44 (на телефоне проверены 0.3.0+3,
определение страны из 0.6.1 и 0.7.0, шар из 0.14.0, вкладки и жесты
карты из 0.15.1, «В этот день», итоги года и фильтр календаря из 0.16.0, планы из 0.17.1),
Flutter 3.47.4, Dart 3.13.3, разработка на macOS.
После согласованной настройки окружения:

```sh
flutter pub get
flutter analyze
flutter test
```

Сейчас 215 тестов, включая golden-сравнения (эталоны на macOS; светлые
390 px — английский, тёмные и узкие — русский). Не обновлять эталоны лишь
для получения зелёных тестов: сначала объяснить расхождение. На другой ОС
возможны отличия рендеринга шрифтов.

Проверять все изменения календарной логики модульными тестами, а UI также
на узком экране 320 px с текстом 180% и в тёмной теме.

APK собирается только для arm64-v8a (`ndk.abiFilters` в
`android/app/build.gradle.kts`): один универсальный файл около 21 МБ вместо
59 МБ с тремя архитектурами. 32-битные телефоны и эмуляторы x86 не
поддерживаются намеренно; не возвращать другие ABI без решения владельца.

## Подпись: обязательная остановка перед APK

Идентификатор `com.domiday.domiday`; установленная у владельца версия 0.3.0
имеет versionCode 3. Для следующего обновления код должен быть больше
установленного.

**Ключ подписи не включён в репозиторий.** Release подписывается через
`signingConfigs.release`, параметры берутся из локального
`android/key.properties` (исключён из Git). Без него упаковка release
падает с ошибкой — это намеренно: сборка, подписанная случайным debug-ключом,
не установится поверх приложения владельца. Не выдавать такую сборку как
обновление и не советовать удалять приложение ради установки.

Перед выдачей APK сверить SHA-256 сертификата (`apksigner verify
--print-certs`) с отпечатком из HANDOFF.md. Не перезаписывать чужой
`~/.android/debug.keystore`. Не коммитить `.keystore`, `.jks`,
`key.properties`, пароли и личные записи; не читать keystore в контекст.
