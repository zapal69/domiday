# Domiday: запуск проекта в Claude Code

Архив содержит исходники Domiday 0.2.0, Android-проект, тесты и локальную
историю Git. Приложение уже реализовано; сначала восстановите рабочую среду,
а не создавайте новый проект поверх этих файлов.

## Начало работы

1. Распакуйте архив целиком, включая скрытую папку `.git`, в удобное место.
   Например, поместите `domiday-android` в `~/Projects/`.
2. Откройте терминал в распакованной папке.
3. Если Claude Code уже установлен, запустите:

```sh
cd ~/Projects/domiday-android
claude
```

Путь выше является примером. Если Claude Code ещё не установлен, используйте
[официальную инструкцию](https://code.claude.com/docs/ru/quickstart).
Назначение файла CLAUDE.md описано в
[документации проекта](https://code.claude.com/docs/en/memory).

Первое сообщение Claude:

> Прочитай CLAUDE.md, START-HERE.md, HANDOFF.md и README.md.
> Пока ничего не меняй и не устанавливай. Объясни структуру Domiday,
> проверь доступную среду разработки и предложи план воспроизведения тестов.
> Для любых изменений сначала дождись моей команды.
> Отдельно проверь условия подписи обновления: ключ в архив не включён.

## Что проверить в окружении

В исходной Linux-среде использовались:

| Компонент | Проверенная версия |
| --- | --- |
| Flutter | 3.47.4, stable |
| Dart | 3.13.3 |
| Java для Gradle | OpenJDK 21 |
| Android compile / target SDK | 36 |
| Android minimum API | 24 |
| Android Build Tools | 36.0.0 |
| Android NDK | 28.2.13676358 |
| CMake | 3.22.1 |
| Gradle wrapper | 9.3.1 |
| Android Gradle Plugin | 9.1.0 |
| Kotlin plugin | 2.4.0 |

SDK, Java, кэши и машинные пути не входят в архив. Версии зависимостей
зафиксированы в pubspec.lock; не обновляйте их одновременно с переносом.
Флаги `android.newDsl=false` и `android.builtInKotlin=false` взяты из
использованного Flutter-шаблона. Не удаляйте их без отдельной проверки.

После согласования установки среды:

```sh
flutter --version
flutter doctor -v
flutter pub get
flutter analyze
flutter test
```

`android/local.properties` отсутствует намеренно: пути Flutter и Android SDK
должны соответствовать вашему компьютеру. Используйте настройку Flutter,
а не пути из исходной среды. При проблеме с правом запуска wrapper на Mac/Linux:

```sh
chmod +x android/gradlew
```

Не выполняйте `flutter create .` поверх проекта без необходимости и проверки
изменений: Android-конфигурация уже настроена.

## Сборка APK: только после настройки подписи

Команда, использованная для прежней ARM-сборки:

```sh
flutter build apk --release --target-platform android-arm,android-arm64 --no-pub
```

**Не устанавливайте сборку на основной телефон, пока не сверен сертификат.**
Release подписывается ключом из локального `android/key.properties`
(см. README, «Подпись release-сборок»); без него сборка release падает,
а не подписывается случайным debug-ключом. Ключ не должен попадать
в репозиторий.

Не удаляйте установленный Domiday и не очищайте данные для обхода конфликта
подписей: пользовательских резервных копий пока нет.

## Что находится в архиве

- `lib/`: код приложения.
- `android/`: Android-проект и Gradle wrapper.
- `test/`: тесты, тестовые шрифты и 16 эталонных изображений.
- `.git/`: история версий 0.1, 0.2 и отдельный коммит передачи.
- `CLAUDE.md`: рабочие правила для ИИ.
- `HANDOFF.md`: состояние проекта, архитектура и ограничения.
- `README.md`: подробности функций и тестов.

Здесь нет данных с телефона, списка подписчиков, сайта, APK, ключей подписи,
токенов, SDK и больших сборочных кэшей. Перенос исходников сам по себе
не переносит личный дневник с телефона на компьютер.
